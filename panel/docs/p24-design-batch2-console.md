## 2. 操作台 UI（范围与交互）

### 2.1 布局

现「体检结果（doctor dry-run · 只查不改）」区块升级为「**体检与操作台**」，三个分组：

1. **可执行（2 类）**：每条卡片＝severity 标签＋message＋`id · file:line`＋**「执行」按钮**（rewrite 级）；
2. **建议（20 类 manual）**：只读列表，原样式不变，无按钮；`reg.name-collision` 等引擎原文含「需要人工决策」者照原样呈现；
3. **空态**：「✓ 没有发现任何问题」照旧。

### 2.2 执行流（两步，Q-C 级 1）

```
点「执行」 → POST doctor/apply/plan（body: issueId）
            服务端：fresh dry-run → 定位该 issue → 校验 fix.plan 非空且 class=rewrite
            → 返回计划预览（算子步骤/目标文件/old→new diff/回滚提示）＋ plan token（时效复用既有 putPlan 机制）
→ 确认页（§3 文案）单次确认 → POST doctor/apply/execute（body: token, change:true）
            服务端：spawn CLI（D1：--only <issueId> --yes --json）→ 退出码/备份根/逐 step 结果回传
→ 自动复检（spawn dry-run）→ 展示「复检：error N, warning M」＋备份位置＋回滚入口指引
```

- **一次只执行一条**（`--only` 单 issue 语义，天然杜绝 CLI「整轮批量」语义进入面板）。
- `install-package` 特例：plan 阶段即解析本地源（`file:`／installSources）——无源 ⇒ plan 直接拒绝（`mount-no-receipt` 同款人话），确认页按钮不出现；有源 ⇒ 预览展示「本地源路径＋版本 X／声明范围 Y」。
- **fresh dry-run 前置**：plan 必须基于**当下**的 dry-run 报告（不复用页面上旧体检结果），防报告过期错位；issueId 不在 fresh 报告中 ⇒ plan 拒（`issue-no-longer-present`）。

### 2.3 禁用态（含本轮固化惯例）

- doctor CLI 不可达/超时 ⇒ 操作台区整体禁用＋说明「体检服务不可用」。
- **「待上架禁用态」惯例（判定 2026-09-19 固化，全项目适用）**：功能完整交付但未过上架前置（判定侧验收／用户目视／用户备份确认）时，**入口一律渲染为 disabled＋「待激活」提示**，不得以可用形态暴露。本批施工自身适用：若某入口依赖的用户确认未到位，按此惯例处理。

## 4. 双回滚 UI（Q-B 裁定：与操作台同批）

### 4.1 体检回滚段（doctor 域）

- **数据源（D2）**：面板**只读**解析 `~/.dsh/doctor-patch-state.json`（rollbackChain：stamp／action／createdAt／备份根／影响文件数）。理由：读不是写，不动 doctor CLI；文件不存在 ⇒ 空态「还没有可以回滚的体检操作」；结构非法 ⇒ 显示「记录不可读，请改用命令行方式回滚」（不擅自清账）。
- **执行**：spawn CLI `--rollback --to <stamp> --json`。**如实申报一处平台事实**：CLI 的 rollback **自身无确认层**（`executor.mjs:511-530` 无 confirm 回调）——因此面板自建两步（plan=展示将恢复清单＋token；execute=spawn），Q-C 单次确认在 UI 层补齐；CLI 侧的 protected 断言／备份缺失 fail-closed 原样生效。
- 回滚完成后自动复检（dry-run）并刷新回滚列表（chain 追加了 rollback 条目，可再回滚）。

### 4.2 配置快照恢复段（面板域，D3）

- **数据源**：`backupRoot`（`.panel-write-backups/`）既有目录扫描——每 stamp 的 `manifest.json`（reason/note/时刻）＋ pre 镜像 sha／字节数（L-058 已字节级证明该链可完整往返）。
- **实现路径（D3，设计决策呈预审）**：apply-engine 新增受控算子 **`restoreSnapshot`**——以快照全文为目标文本整文件写回 `cordis.patch.yml`，安全链全套照用（plan 时锁定 expectedSha=当前 sha、写前必备份、`assertPatchUnchanged`、execute 时 sha 不符即中止）。理由：整文件恢复无法用「摘行＋插回」可靠模拟；给唯一通道加一个显式恢复算子，比让用户手搬文件或绕道判据级脚本更安全。**备选 (b)**：批 2 不做面板备份段恢复，仅呈现备份列表（回滚路径=3.3/3.3 之外改用 CLI 判据脚本）——若判定侧认为动 apply-engine 的风险大于收益。
- 列表只展示**最近的快照**（默认 5 条），每条：时刻／reason（panel-uninstall-soft 等）／pre-sha 前 8 位／「恢复」按钮（级 1 确认页 3.4）。

### 4.3 收据对账段（只读）

见 §3.5；数据源＝既有 `custody` 路由（`listCustody`，`mountable` 字段照旧）。

## 6. 工程实现要点

### 6.1 新路由（面板域；guard 全套，写路由标 `{change:true}`）

| 路由 | 方法 | 语义 |
|---|---|---|
| `/api/toolkit-panel/doctor/states` | GET | 只读：patch-state 回滚链列表（D2 容错）＋面板备份快照列表（4.2 数据源） |
| `/api/toolkit-panel/doctor/apply/plan` | POST | 单 issue 计划预览（fresh dry-run 前置） |
| `/api/toolkit-panel/doctor/apply/execute` | POST | spawn CLI `--apply`（D1） |
| `/api/toolkit-panel/doctor/rollback/plan` | POST | 指定 stamp 的恢复清单预览 |
| `/api/toolkit-panel/doctor/rollback/execute` | POST | spawn CLI `--rollback --to` |
| `/api/toolkit-panel/snapshot-restore/plan` ＋ `/execute` | POST | D3：restoreSnapshot 两步 |

路由数 15 → **21**（p1-smoke 同步更新 gate 断言）。

### 6.2 doctor CLI 两处小改（**D1，doctor 域代码改动，随本稿过审后施工**）

1. **`--only <issueId>`**：`--apply` 时只执行该 issue 的 fix plan（issueId 白名单校验 `[a-z0-9._-]+`，防注入）。动机：CLI 现为「整轮批量」语义，面板需要单条语义；由 CLI 原生支持可避免面板落临时过滤报告文件。
2. **`--yes` 语义澄清**：非交互下 `--apply` 需 `--yes`（现文案「仅供测试」）——语义升级为「**调用方已完成逐条知情确认的受托执行**」，面板在 UI 层承担 Q-C 确认后再带 `--yes` spawn；CLI 帮助文案同步修改。**风险如实呈现**：`--yes` 在终端里仍是跳过确认，红线不变——写前备份/protected 断言/锚点重验全数保留。

两仓提交互引：doctor 域改动在 doctor 仓提交（附最小自测脚本），面板域在 toolkit 仓提交。

### 6.3 spawn 规范

复用 `panel/manager/doctor-runner.mjs` 模式（execFile、120s 超时、windowsHide、24MB buffer、JSON 解析 fail-safe）；新增参数仅 `--only`／`--yes`／`--to`／`--json`，**全部经白名单拼装**，任何 issueId/stamp 先过字符集校验。
