## 0. 变更摘要

| 项 | v1（存档式，现行实现） | **v2（销毁式，本稿）** |
|---|---|---|
| 真卸载 | 删前把 `lib/<plugin>` 全量镜像到保管区 `body/`，校验通过再删源 | **不复制任何文件内容**；只记「收据」，直接彻底删除 |

## 1. 真卸载流程 v2（去存档步 · 收据先行）

> v1 的「存档 → 校验 → 删源」三步中，**存档与校验两步去掉**；但**收据写入仍必须在删除之前**，且失败即中止（fail-closed）。

1. **计划（只读）**：定位行块 + 宿主键 + **枚举** `lib/<plugin>` 文件清单并**就地计算 sha256 / 字节数**（**只读不复制**）。plan 阶段**绝不删除任何东西**。
2. **用户确认**：真卸载弹窗 v2（§6），**手动输入插件名两次** → 「确认彻底删除」。服务端在 `execute` 阶段**再校验一次**告知性确认（不信客户端，沿用现行）。
3. **执行**：
   1. **收据先行**：写 `.panel-custody/<plugin>-<UTCstamp>/manifest.json`（§3 结构；**无 body/**）。写失败 ⇒ **中止，不执行任何删除**。
   2. **patch 写入走 `executePlan` 唯一通道**：摘挂载行 + （搜索插件）宿主键 unset。SHA / 锚点 / 写前备份闸全数生效。
   3. **彻底删除**：`rmSync(lib/<plugin>, { recursive: true, force: true })`。
   4. **复验**：目录不存在 · 行不残留 · 收据在案 · doctor 无 error（缺席仅提示级）。
4. **收据不承载恢复能力**——UI 明示「仅用于对账，不含文件内容，不能用来恢复」。

### 1.1 与 v1 相同的安全链（不动）
- 两步 plan → confirm → execute；`executePlan` 唯一写盘通道；写前备份；`assertPlanFresh` / `assertPatchUnchanged`；loopback + Host + CSRF + `change:true` + 白名单。
- **新增**：删除动作只在 `execute` 阶段发生，plan 阶段恒只读。

### 1.2 compact-router 特案（预设管理）
- 流程 = `apply-preset-patch.mjs --undo` → 收据先行 → 删 `lib/compact-router`。
- 预设回写仍**只调既有脚本**（双层留痕、`preset-backups/`、`preset-patch-state.json`）——本稿不变。

## 2. 收据（receipt）口径

> **一句话**：收据是**删除的账**，不是**恢复的档**。

| 字段 | 内容 | 用途 |
|---|---|---|
| `schemaVersion` / `kind` | `true-uninstall-receipt` | 与 v1 存档型区分 |
| `plugin` / `pkg` / `createdAt` | 插件标识与时刻 | 对账 |
| `userReason` / `confirmCopy` | 用户填写原因 + 确认页文案快照 | 审计（**无虚假承诺**的判据） |
| `deleted.body[]` | `{ rel, origAbs, sha256, bytes }` 逐文件 | **事后对账**：删了什么、内容指纹是什么 |
| `deleted.totals` | 文件数 + 总字节数 | 对账 |
| `rebuild.rowBlock` | 挂载行块原文（**配置片段，非源码**） | **重装后挂载**（§5） |
| `rebuild.hostKey` | `{ key, raw, relOffsetWithinConfig, afterKeys }` | 重装后宿主键回写 |
| `rebuild.presetStateSnapshot` | compact-router 专用 | 重装 |
| `body` | **不存在**（**硬约束**：收据目录下**不得**出现 `body/`） | —— |

- **边界声明**：收据**不含任何源代码文件内容**；`rowBlock` 与 `hostKey` 是**配置元数据**（挂载位置与设置键），保留它们才能实现「重装后挂载」。此边界请判定侧确认（§10-Q2）。
- **目录沿用 `.panel-custody/`**（`.gitignore` 已忽略，避免改名churn）；`manifest.kind` 改为 `true-uninstall-receipt`。目录名仍叫 custody 属**历史命名债**，本稿记注记不改名（§10-Q3）。

## 5. 重装支持（§④修订范围）

### 5.1 用户故事（终验段 2 的骨架）
```
真删除(销毁) → reload（缺席态 + dependency-broken）
  → 模拟重装：外部副本放回 lib/<plugin>
  → 面板检测「已安装未挂载」(installed-unmounted)
  → 点「挂载」；重启 → 复原 + 联动自动恢复
```

### 5.2 检测（已有，不改）
`installed-unmounted` = 本体在 + 行不在 + **无面板软卸载台账**（现行实现已覆盖；「面板外放回 lib」正是这一态）。

### 5.3 挂载算子（新增，**复用插回算子**）
- 复用 `planInsertRow`（锚点唯一 + SHA + 写前备份），走 `executePlan` 唯一通道。
- **行块来源两路**：
  1. **有收据** → 用 `receipt.rebuild.rowBlock` + `hostKey` 原值/原位置（最保真，含宿主键原值）。
  2. **无收据**（外部删除后重装 / 从未经面板卸载）→ 行块由 `plugin-registry` 的**内置模板**生成；宿主键置 **schema 缺省（unset）**，等同「新装」。
- 宿主键冲突：挂载时若宿主键已被占用 → 沿用**冲突三态** A/B/C（不自动覆盖）。
- 新增 API：`POST /api/toolkit-panel/mount/plan` + `/mount/execute`（`{change:true}` + 全套 guard）。

### 5.4 挂载后状态
`installed-unmounted` →（挂载）→ `mounted`；重启后生效；doctor 提示消失。

## 9. 不可逆风险与安全网（**请务必逐条裁决**）

| # | 事实 / 风险 | 本稿建议 |
|---|---|---|
| R1 | `rmSync(..., {force:true})` **绕过回收站** —— 删除后**文件不在回收站**，系统层面也找不回 | 弹窗如实写明；**不得**使用户误以为「删了还在回收站」 |

| R3 | 未开源前**无任何获取途径** | **强烈建议**：动工前由**用户自行**在仓外（如压缩包 / 另一磁盘）**人工备份五插件源码**。这是用户侧动作，**不违反**「面板不留副本」，且是唯一兜底 |
| R4 | 误操作代价 = 源码永久丢失 | 已有多因素：plan 只读预览 + 输入名两次 + 中间展示空窗期警告 + 按钮文案含「彻底」 |
| R5 | 删除前无法复核内容 | 建议弹窗展示**将删文件清单 + 总字节数**（来自 plan 的只读枚举），确认前可见（§10-Q5） |
